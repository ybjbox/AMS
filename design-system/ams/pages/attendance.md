# 考勤管理（/attendance）· 页面规则

## 为什么这个页面要重排

考勤不是四个并列的功能页，是一条**有前置依赖**的流水线：

```
①配部门时段 ──> ②导打卡记录 ──> ③分析异常 ──> ④月度报表
     (前置)          (输入)          (判定)         (产出)
```

原先是四个平铺标签、顺序为「打卡记录 / 部门时段 / 异常分析 / 月度报表」，
前置条件夹在第二位且藏在一个 20KB 的配置表后面。后果不是难看，是**误导**：
最常见的现场是"异常 0 条"，而它有两种完全不同的成因 —— 还没分析 / 分析过确实没人异常。
空状态里那句话只写在"0 条异常"分支里，用户没走到那儿就永远看不到。

现在标签栏只剩**三个**：打卡记录 / 异常分析 / 月度报表。部门工作时段搬进了弹窗 ——
它配好后基本不动，而另外三个每天都要看，把它和日常视图平级摆着本身就是误导。
第 ① 步仍留在工作流条上（点它**开弹窗**，不切标签），另给一个页头按钮兜底。

## 结构：工作流条取代标签栏

- `WorkflowBar` 同时承担**导航**与**进度**，不要再加一层 `tab-group`（两条导航重复）。
- 不在标签位上的东西用步骤上的 `opensDialog` 标记，不要为了放得下再加回一个标签。
- 状态推导集中在 `lib/workflow.ts` 的 `deriveWorkflowSteps()`，单测钉住。
  任何地方要显示"还欠什么"都问它，不各自写 if。
- `blocked`（缺前置）= 强行继续会得到**误导性空结果**的步骤，而不是"还没做"。
  两条：时段为 0 → 打卡/分析 blocked；打卡为 0 → 分析/月报 blocked。
- 每一步都可直接点击。不是强制线性向导 —— 只看月报的老用户不该被四步挡住。

## 密度：DEFAULT_DENSITY = 4/5（比 MASTER 密）

| 元素 | 取值 | 理由 |
|---|---|---|
| 统计 | 一条 4 格横带，`py-3` 单行（原先四张卡各 120px 高） | 1370×770 @200% 下，四张卡把表格全挤到折叠线以下 |
| 数值 | `text-lg` + `tabular-nums` | 切筛选时数字宽度不变，不左右跳 |
| 表格行 | `px-4 py-2`（原先 `px-6`） | 列多 6 列时 `px-6` 会把 min-width 撑到 800px+ |
| 筛选栏 | 单行 `card-base p-4`，搜索/日期/来源并排 | 筛选器不该比它筛的数据更抢眼 |

## 筛选：筛选器是必需品，不是增强

MASTER 的设计系统反模式清单里明确列了 **"No filtering"**。本页的具体门槛：

- 打卡记录必须能按 **姓名/工号 + 日期区间 + 来源** 筛选。1897 条只能翻页 = 不可用。
- 异常必须能按**处置方式**分组（迟到 / 缺卡 / 早退），而不是按枚举值罗列五个：
  `LATE_5` 与 `LATE_15` 都是迟到，`MISSING_IN` 与 `MISSING_OUT` 都是缺卡。
  分组计数必须与表格过滤结果条数一致（同源函数 `lib/filters.ts`，有单测）。
- 前端筛选而非服务端分页：`records` 已在 store 里全量，`records.length` 同时供统计卡，
  再分页会出现两份真相。真要分页时替换 `lib/filters.ts` 三个函数即可，组件签名不变。
- 筛选结果为空 ≠ 没数据：空状态文案必须区分"没数据"与"没匹配"，并给清除筛选的出口。
- 筛选变化后分页必须回第 1 页（渲染期就地修正，不要 `useEffect` + `setState`）。

## 深链：标签走 `?tab=`

与 `PrintTools`、设置页同一套做法。非法值（含旧书签的 `?tab=schedules`）
回落到第一个标签，不报错也不白屏。默认落在第 ① 步而不是"最有数据"的那步 ——
新库进来第一眼应该是"还差什么"，不是一张空表。

⚠️ 标签**移走**之后同样要管老书签：`?tab=shift-rules` 现在会回落到「打卡记录」。
时段从工作流条第 ① 步或页头按钮进。这不是 bug，是有意的（见上），
但要在 `TabType` 与校验处留注释，别让下一个人以为是回归。

## 状态语义

| 状态 | 语义色 | 用在 |
|---|---|---|
| 已完成 | emerald（700/400 档） | 工作流步骤、满勤 |
| 缺前置 | amber（700/400 档） | 工作流步骤、顶部横幅 |
| 可进行 | brand 蓝 | 工作流步骤、选中态 |
| 异常-迟到/早退 | warning | Badge |
| 异常-缺卡 | destructive | Badge |

> 异常徽章颜色按**处置成本**分，不按严重程度分：缺卡要补证明（红），
> 迟到扣钱（黄），早退已发生、改不了（中性）。

## 本页专属约束

- 页头**不放**导入/分析按钮之外的东西；主操作随标签切换（打卡 → 导入，异常 → 分析）。
  「部门时段」按钮是例外 —— 它替代的是一个被移走的标签，不加它就少了一个入口。
- 「清空全部记录」是破坏性操作：必须有 `attendance:purge` 权限 + `useConfirm`，
  且标题里带上真实条数。
- 删除单条记录用 icon 按钮 + **完整中文 `aria-label`**（对象 + 日期 + 时间），
  不能只有 `title`。
- 原生 `<input type="date">` 必须带 `dark:[color-scheme:dark]`（MASTER Form fields）。
- 筛选栏的来源/类型切换用 `role="group"` + `aria-pressed`，不用 radio。
