# 行业对标与功能改进路线图

调研时间：2026-07-31
对标对象：钉钉、飞书、企业微信、Moka、薪人薪事、北森、用友、Workday、SAP SuccessFactors

---

## 一、当前系统能力盘点

AMS 现有模块：**员工管理、组织架构、考勤管理、文档管理、合同管理、座位管理、导出（Excel/打印）**。

定位判断：这是一套**"人事档案 + 基础考勤"型系统**，覆盖了 HR 数据底座，但缺少两大块：
1. **行政服务闭环**（审批、报修、会议室、资产、访客）
2. **智能化分析**（异常洞察、风险预警、效能诊断）

---

## 二、行业调研关键结论

### 2.1 三大协同平台的行政能力分布（2026 实测对比）

| 行政场景 | 飞书 | 钉钉 | 企业微信 | AMS 现状 |
|---------|------|------|---------|---------|
| 会议室管理 | ★★★★★ 日历集成/屏幕联动/利用率分析 | ★★★★ 预约+审批+硬件 | ★★★ 基础预定 | ❌ 无 |
| 考勤打卡 | ★★★ 复杂排班弱 | ★★★★★ 行业最强（弹性工时/GPS/人脸） | ★★★★ 多模式 | ⚠️ 有排班+异常分析，无打卡采集 |
| 审批流程 | ★★★★ 移动端友好 | ★★★★★ OA 引擎最成熟 | ★★★★ 基础模板 | ❌ 无 |
| 资产管理 | ★★★★ 多维表格搭建 | ★★★★★ 一物一码全生命周期 | ★★ 需第三方 | ❌ 无 |
| 工位管理 | ★★★★ | ★★★★ 宜搭模板 | ★★ | ✅ 有座位管理 |
| 报修管理 | ★★★★ 服务台+SLA | ★★★★★ | ★★★ | ❌ 无 |
| 员工服务台 | ★★★★★ AI问答+工单+知识库 | ★★★★ | ★★★ | ❌ 无 |
| 数据看板 | ★★★★★ | ★★★★ | ★★ | ⚠️ 基础统计 |
| 车辆/车位 | ★★★ | ★★★★ | ★★ | ❌ 无 |

**读法**：AMS 在"档案+工位"上已达到可用水平，短板集中在**审批流、资产、服务台**三块——而这三块恰恰是行政日常工作量占比最高的部分。

### 2.2 2026 年 HR / 行政 SaaS 的四条主线

1. **AI 原生重构**：不再是"加个 AI 助手"，而是把 AI 做成"AI 同事"。Moka 的 Eva 可独立完成招聘筛选、人事问答、HRBP 分析；钉钉用 OCR 自动识别发票填报销单、AI 判断审批路由和风险预警。
2. **一体化数据互通**：组织 → 假勤 → 薪酬 → 绩效自动流转，杜绝"考勤表导出再手工贴到工资表"。用友 YonGPT 的"业人融合"、Workday 的 "Power of One" 都是这个思路。
3. **合规与溯源**：多租户安全隔离、云端全链路留痕、动态水印防泄密、登录风控。这是从"能用"到"敢用"的分水岭。
4. **员工自助 + 主动预警**：员工自己查年假余额、报异常、提申请；系统主动推送"社保将断缴""合同 30 天后到期""考勤异常待确认"，而不是等 HR 去翻表。

## 三、改进建议（按 ROI 排序）

### 🥇 第一梯队：补齐行政闭环（投入小、感知强）

#### R1. 通用审批流引擎 ⭐⭐⭐⭐⭐
**为什么**：这是行政系统的心脏。没有审批流，请假、加班、报销、用章、采购全都要走微信+Excel，AMS 就永远只是个"查档案的地方"。

**建议实现**：
- 数据模型：`approval_templates`（表单 schema + 流程节点 JSON）、`approval_instances`、`approval_tasks`
- 支持：串行/并行审批、条件分支（金额 > 5000 加签总监）、抄送、加签/转交、撤回
- 复用现有资产：`departments` 树可直接做"逐级上报"节点解析；`systemRole` 做角色节点
- 前端：拖拽式流程设计器（可先做配置表单版，不做画布）

**关联现有模块**：请假审批通过后**自动写入 `schedules`**，考勤异常分析时自动排除已批假期——这就是"一体化数据互通"的第一个落地点。

#### R2. 员工自助门户 ⭐⭐⭐⭐⭐
**为什么**：当前所有页面都是 HR 视角。45 个员工的公司还行，200 人以上 HR 会被"帮我查一下我的年假"淹没。

**建议实现**：
- 独立的 `/portal` 路由与精简导航（登录后按 `systemRole` 分流：EMPLOYEE → portal，HR/ADMIN → 现有后台）
- 我的档案（只读+发起变更申请）、我的考勤（打卡记录/异常申诉）、我的假期余额、我的合同、我的工位
- **前置依赖**：P0-3 真实登录 + P0-4 服务端权限（见 AUDIT.md）

#### R3. 资产管理（一物一码） ⭐⭐⭐⭐
**为什么**：钉钉在这块是五星，说明这是行政刚需。电脑、显示器、门禁卡的领用归还，目前多数公司还在用 Excel。

**建议实现**：
- `assets` 表（编号/类目/品牌型号/采购日期/价格/状态/当前持有人/存放位置）
- `asset_records` 流水表（领用/归还/报修/报废/调拨）
- 二维码：`qrcode` 生成资产标签，扫码即入详情页
- **与员工联动**：离职时自动检查"该员工名下是否还有未归还资产"，挡住离职流程

#### R4. 会议室预定 ⭐⭐⭐⭐
**建议实现**：`meeting_rooms` + `room_bookings`，时间轴视图（横轴时间/纵轴会议室）防冲突，支持周期性预定；后期可出**利用率分析**（哪间会议室常年空置 → 改成工位）。

---

### 🥈 第二梯队：智能化（差异化亮点）

#### R5. 智能考勤分析与主动预警 ⭐⭐⭐⭐⭐
**为什么**：AMS 已经有了 `analyzeAnomalies()` 真实规则引擎（LATE_5 / LATE_15 / MISSING_IN / MISSING_OUT / EARLY_LEAVE），这是**现成的地基**，往上加一层分析成本极低、效果极显著。

**建议增量**：
| 能力 | 实现思路 |
|------|---------|
| 异常趋势看板 | 按部门/月份聚合异常率，红黄绿灯 |
| 个人异常画像 | "张三近 30 天迟到 8 次，环比 +60%" |
| 加班时长统计 | 从打卡记录推算，识别"连续加班 > 10 天"疲劳预警 |
| 部门出勤健康度 | 综合出勤率+异常率+加班强度打分 |
| 异常申诉流 | 员工在 portal 提申诉 → 走 R1 审批流 → 通过后自动修正记录 |

#### R6. 合同与证件到期主动预警 ⭐⭐⭐⭐
**为什么**：`employees` 表已有 `contractExpiry` 和 `daysToExpiry` 字段，**数据都在，只差一个提醒机制**——这是最低成本的高价值功能。

**建议实现**：
- 后端定时任务（`node-cron`）每日扫描：合同 60/30/7 天到期、试用期转正、社保断缴（`hasSocialSecurity=0` 且在职）、生日/司龄周年
- 站内通知（`notifications` 表落库，替换现在的纯前端 store）+ 可选邮件
- Dashboard 顶部"待办卡片"：本月 3 份合同到期、2 人试用期届满

#### R7. 离职风险与组织效能诊断 ⭐⭐⭐
**为什么**：这是北森/Moka 的高端能力，但用现有数据就能做出 70% 效果。

**建议实现**（基于规则而非黑盒模型，可解释）：
- 风险信号：司龄 1.5-3 年（跳槽高发期）+ 近 3 月异常率上升 + 长期无晋升记录（`changeStatus='无'`）+ 加班强度骤降
- 组织维度：人才密度（各部门司龄/职级分布）、管理幅度（一个 leader 带几人）、部门流失率排行

#### R8. AI 员工助手 ⭐⭐⭐
**为什么**：2026 年的标配。但建议**放在第二梯队**——先有审批流和自助门户，AI 才有东西可查可办。

**建议实现**：
- 阶段一：自然语言查询（"研发部有多少人""这个月谁迟到最多"）→ 转 SQL 查询
- 阶段二：办事（"帮我请下周一的假" → 自动填单并提交 R1 审批流）
- 阶段三：主动汇报（每周一自动生成"上周人事异动 + 考勤概览"推送给 HR）

---

### 🥉 第三梯队：合规与体验

#### R9. 全链路操作审计 ⭐⭐⭐⭐（同 AUDIT.md 的 P1-5）
不只是修 bug，更是**合规能力**：谁在什么时间改了谁的什么字段、改前改后值分别是什么。等保二级、ISO 27001 的硬性要求。建议同时做**敏感字段脱敏展示**（身份证只显示 `440106********1234`，点击"查看完整"记一条审计）。

#### R10. 数据看板升级 ⭐⭐⭐
从"几个数字卡片"升级为**行政数据驾驶舱**：人员结构（部门/司龄/学历/用工类型饼图）、人员流动（月度入离职趋势）、考勤健康度、合同风险、资产统计。飞书在这块五星，说明可视化本身就是竞争力。

#### R11. 报修与服务台 ⭐⭐⭐
`tickets` 表 + SLA 计时 + 满意度评价。可复用 R1 审批流的流转引擎，增量成本低。

#### R12. 访客管理 ⭐⭐
预约登记 → 生成二维码 → 到访核销 → 被访人通知。中小企业需求偏弱，排最后。

## 四、推荐路线图

```
Phase 0 · 安全加固（1-2 周）  ← 必须先做，否则一切功能都是沙上建塔
   ├─ 修复 RCE / API 鉴权 / 真实登录 / 服务端权限（AUDIT.md P0 全部）
   └─ 审计日志 + 数据备份（R9 前半 + P1-7）

Phase 1 · 行政闭环（3-4 周）
   ├─ R1 审批流引擎          ← 心脏，优先级最高
   ├─ R2 员工自助门户
   └─ R6 到期预警（成本最低，可穿插做）

Phase 2 · 资产与空间（2-3 周）
   ├─ R3 资产管理（一物一码）
   ├─ R4 会议室预定
   └─ R11 报修服务台（复用 R1 引擎）

Phase 3 · 智能化（3-4 周）
   ├─ R5 智能考勤分析        ← 现有 analyzeAnomalies 直接升级，ROI 最高
   ├─ R10 数据驾驶舱
   └─ R7 离职风险与组织诊断

Phase 4 · AI 与合规（持续）
   ├─ R8 AI 员工助手
   ├─ R9 审计后半（脱敏 + 水印）
   └─ R12 访客管理
```

## 五、一句话结论

**AMS 的数据底座（员工/组织/考勤/文档/合同）已经打得不错，考勤异常分析甚至是真实规则引擎而非摆设。但它现在是一个"档案柜"，不是一个"办事大厅"。**

要变成后者，最关键的一步是 **R1 审批流引擎 + R2 员工自助门户**——它们把系统从"HR 单方面录入"变成"全员参与流转"，而这正是钉钉/飞书能成为行政 OS 的根本原因。

在此之前，请务必先修掉 AUDIT.md 里的 4 个 P0，尤其是 **P0-1 的 RCE 漏洞**——那是一个可以被任何人两个请求接管服务器的洞。
