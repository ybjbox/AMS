## 4. 11 条部门时段（唯一只存在于数据库里的业务口径，原样抄）

来源：`ams-重装备份\dept-shift-rules.json`（机器可读，重配时对着填）

| 部门 | 时段名 | 上班 | 下班 | 上班卡没打按缺卡记 | 加班余量 |
|---|---|---|---|---|---|
| 停车收费组 | 大夜 | 00:00 | 08:00 | 否 | 120 |
| 停车收费组 | 早班 | 08:00 | 16:00 | 否 | 120 |
| 停车收费组 | 小夜班 | 16:00 | 24:00 | **是** | 120 |
| 夜班组 | 大夜 | 01:00 | 08:00 | 否 | 120 |
| 夜班组 | 小夜 | 17:30 | 01:00（次日） | 否 | 120 |
| 市场部办公室 | 办公室班 | 08:30 | 18:00 | **是** | 120 |
| 消防监控组 | 大夜 | 00:00 | 08:00 | 否 | 120 |
| 消防监控组 | 早班 | 08:00 | 16:00 | 否 | 120 |
| 消防监控组 | 小夜班 | 16:00 | 24:00 | **是** | 120 |
| 管段、物业、水电组 | 常规班次 | 08:00 | 18:00 | **是** | **300** |
| 管段、物业、水电组 | 连班 | 08:00 | 16:00 | **是** | **300** |

- 工作日：全部为「每天」（7 天）。
- 「加班余量」= 末卡允许超出下班点多少分钟。管段组配 300 的原因：实测有人干到 22:05（超 245 分钟），
  按默认 120 会被丢成「未归属卡」。
- 「上班卡没打按缺卡记」= 首卡与上班时间差过容忍时，记「缺上班卡」而不是判「没对上班」。
  三个部门开了（管段/市场部办公室/两个小夜班-16:00 那班），其余保持「对不上就不判」。
- 早退超过 60 分钟改记「缺下班卡」（分不清早走还是忘打卡时不猜）—— 这条是全局缺省，没在表里。

## 5. 考勤判定口径速查（2026-10-09 逐条与用户确认过）

| 项 | 口径 |
|---|---|
| 对班方式 | 按当天第一次打卡时间自动对部门时段；部门没配就沿用上级部门；再没有就回退逐日排班（界面已撤，仅服务端兜底） |
| 对不上班 | **不判定**，计入覆盖率并在「异常分析」页列出原因（不静默丢弃） |
| 迟到 | 严格 `>` 5 分钟 / `>` 15 分钟两档。**5 分整不算迟到** |
| 早退 | 严格 `>` 0 分；超过 60 分改记「缺下班卡」 |
| 单张卡 | 按班次中点判缺上班卡 / 缺下班卡 |
| 跨零点 | 班次按「实例」切：17:30–01:00 次日的 00:5x 下班卡归**前一天**那班，当天不重复计出勤 |
| 请假日 | 已批准的请假当天不判、不计应出勤 |
| 多部门 | 打卡表给的是多段串（`市场部;市场部/夜班组`），**只存最深的一段** |
| 末卡超出容忍且晚于下班点 | 保持「未判定」，不当成异常 |
| 月报默认月份 | 落在**最近有打卡的月份**，不是当月（当月常只有 1~2 天） |
| 出勤率（看板） | 出勤人日 ÷ 应出勤人日，分母**只算到最近一次打卡为止**（还没导入数据的将来日不算缺勤） |

### 6.1 本机连不上 github.com 时的下载姿势

`winget`/`npx` 默认都去 github.com，本机 443 不通（`0x80072efd`）。
nodejs.org、registry.npmjs.org、registry.npmmirror.com 都通，所以走镜像：

```powershell
# Git for Windows
# 索引是 JSON 目录列表：https://registry.npmmirror.com/-/binary/git-for-windows/
$u = "https://registry.npmmirror.com/-/binary/git-for-windows/v2.56.0.windows.2/Git-2.56.0.2-64-bit.exe"
Invoke-WebRequest -Uri $u -OutFile "$env:TEMP\git.exe" -UseBasicParsing
Start-Process "$env:TEMP\git.exe" -ArgumentList '/VERYSILENT','/NORESTART','/NOCANCEL','/SP-' -Wait

# Playwright 浏览器
$env:PLAYWRIGHT_DOWNLOAD_HOST = "https://cdn.npmmirror.com/binaries/playwright"
npx playwright install chromium
```

> `git pull` / `git push` 同样连不上远端，只能用本地提交。远端真要同步时换网络。

## 7. 三个容易踩的坑

1. **后端必须 `npm run dev:watch`**，不能用 `npm start`。
   `npm start` 跑的是上一次构建的产物，本轮曾因此对着 6 天前的后端排查半天。
2. **`AMS_SEED_DEMO`**（`server/db.ts` 的 `demoSeedEnabled()`）：演示数据（45 个「员工 N」、演示部门树、
   默认班次/文件夹）**默认不播**，这是有意为之 —— 免得假员工和真人混在一张表里。
   - 本地想看演示数据：设 `AMS_SEED_DEMO=1`
   - **e2e 依赖演示数据**，`playwright.config.ts` 的 `webServer` 已带 `AMS_SEED_DEMO=1`，
     别当成多余开销删掉（本轮删过一次，CI 直接红成 12 分钟超时）
   - ⚠️ **本地 `npm run test:e2e` 会污染真实库**：`webServer` 是 `npm run dev` + `reuseExistingServer`，
     DATA_DIR 落到 `./data`，而 e2e 用例会建员工/建部门/建单据。跑之前先停掉 :3000，
     并把 DATA_DIR 指到一次性目录：
     ```powershell
     # 先停掉占着 3000 的 dev:watch
     Get-NetTCPConnection -LocalPort 3000 -State Listen | % { Stop-Process -Id $_.OwningProcess -Force }
     $env:DATA_DIR = "$env:TEMP\ams-e2e-data"; Remove-Item $env:DATA_DIR -Recurse -Force -EA SilentlyContinue
     npm run test:e2e
     Remove-Item $env:DATA_DIR -Recurse -Force
     ```
3. **PowerShell 里带中文的命令**：本机常驻 shell 是旧版，`-Command` 会把中文按 ANSI 解析报错。
   用 `pwsh -NoProfile -EncodedCommand <UTF-16LE base64>`，命令内先设 `[Console]::OutputEncoding=UTF8`。
4. **项目与 TEMP 不在同一盘时，`os.tmpdir()` → DATA_DIR 的 `rename` 会 EXDEV**。
   2026-10-11 项目挪到 `E:\` 后暴露：品牌上传（登录页背景 / 系统图标）直接 500
   （`fs.renameSync` 跨盘报 `cross-device link not permitted`）。
   已在 `server/brandingDb.ts` 的 `commitTmpFile()` 里加 EXDEV 兜底：先拷进目标目录再同盘 rename，
   仍保持原子。**换盘符或改 `DATA_DIR` 到别的卷时，留意还有没有别处从 `os.tmpdir()` 搬文件。**

## 9. 本轮做过的判断（防止以后推翻自己）

| 判断 | 原因 |
|---|---|
| 演示数据默认不播种 | 空库自动播种曾导致「45 假 + N 真」混库，2026-10-10 专门写过一次性迁移脚本清理 |
| 迁移脚本加「有真实数据就拒绝执行」守卫 | 它是推倒重建脚本，重跑会静默删掉 1897 打卡 + 11 条时段 |
| 看板/热力图与考勤共用 `attendanceWindowStats` | 原来看板自己抄了一份简化判定，排班界面撤掉后直接算成空卡 |
| 出勤率分母截到最近一次打卡 | 把还没导入数据的将来日算缺勤，出勤率会凭空低三四成 |
| 部门出勤率按「人日」而非「班次实例」 | 一天两班的员工会让人日数和实例数对不上（实测差 6） |
